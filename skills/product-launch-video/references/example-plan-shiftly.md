# Shiftly launch video: script and first storyboard (v0)

Product: Shiftly, scheduling for restaurant managers. Brand gradient coral `#ff7a59` > pink `#f24e8c` > violet
`#7b5cff`, Inter / Inter Display. Target length about 90 s, 16:9, 30 fps. UK spelling ("labour", "rota"), as in the brief.

Defaults I chose (tell me if any is wrong): audience is owners and general managers of independent restaurants;
voice is one warm female voice on ElevenLabs v3; music is a licensed track to be picked (drop on "Introducing
Shiftly"); no logo file was supplied, so the storyboard uses a placeholder mark (three staggered shift bars in the
brand colours) and the name set in Inter Display.

## Voice-over script (ElevenLabs v3, one clip per block)

Generate 2 or 3 takes per line and keep the same voice and settings for all of them. Drop `[sighs]` if it sounds
overdone.

1. Statement
```
[calm, warm] Every week, restaurant managers lose hours to the staff rota.
```
2. Tool sprawl
```
[matter-of-fact] Juggling spreadsheets, group chats, the till and payroll. Ten different tools for one week of shifts.
```
3. Group chat
```
[slightly frustrated] Then the messages start. Who can cover Friday? [sighs] Who swapped with who?
```
4. Problems
```
[tired] Last-minute swaps, surprise overtime, and a labour bill that's over budget again.
```
5. The turn (same scene, after the list)
```
[hopeful] But what if scheduling could be simpler, with everything in one place?
```
6. Reveal (on the music's drop)
```
[confident] Introducing Shiftly.
```
7. Drag-and-drop planning
```
[warm] Drag a shift onto the week, and watch hours and labour costs update as you plan.
```
8. Swap requests
```
[friendly] Staff ask to swap in the app. You approve with one tap.
```
9. Labour forecast
```
[clear] See next week's labour cost before you publish the rota.
```
10. Weekly AI summary
```
[thoughtful] And every Monday, AI reads the week ahead and flags who's heading into overtime.
```
11. Proof
```
[pleased] Managers finish the rota in twenty minutes, not four hours.
```
12. But wait
```
[playful] But wait... [excited] there's more.
```
13. Montage
```
[upbeat] Drag-and-drop shifts, swap requests, labour forecasts, overtime alerts, staff availability, time-off requests... [warm] and a lot more.
```
14. Close
```
[warm, confident] Shiftly. Less time on the rota, more time on the floor.
```

## Skill feedback

What was unclear, missing, wrong, or needed a workaround while using `skills/product-launch-video` for this test.

**Wrong or inconsistent with the skill's own rules**
1. The kit still carries the previous brand's teal in places `brand.ts` does not control, which breaks
   non-negotiable 2 ("brand colours only") for any new brand: `glow()` and `glass()` shadows in `look.tsx`
   (`rgba(0,90,120)`, `rgba(4,63,69)`), `MagnetCard` shadow (`rgba(0,110,150)`), cursor drop shadows
   (`rgba(5,40,44)`), the Problems dot and card shadows (`rgba(0,150,200)`, `rgba(0,90,120)`), dial track and ticks
   (`rgba(16,36,42)`) and dial label `#3d5359`, `Ripple`'s default colour `#00b9ef`, and the placeholder logo fill
   `#00b9ef`. "brand.ts is the only file to edit" is therefore not true. Workaround: added `inkRGB`, `shadeRGB`,
   `inkA()`, `shadeA()` to `brand.ts` and replaced every hard-coded value.
2. `Chaos.tsx` hard-codes marketing file names in the background (`sessions (2).csv`, `insights.csv`) with no prop.
   Workaround: added a `files` prop.
3. `Montage.tsx` fan-out grid uses a fixed 230 px column pitch, 300 px row pitch and 4 columns at scale 0.42. Any
   visual wider than about 550 px overlaps its neighbours, including the kit's own 820 px placeholder visual.
   Workaround: added `visualW`, `visualH`, `fanCols` and sized the grid from them.
4. `film.tsx` falls back to 90 frames when a scene name is missing from `timing.json` (`durs[b.name] ?? 90`), so a
   typo silently makes a 3 s scene. It should warn or throw.
5. Units differ between scenes: `Montage` takes `at` in seconds, while `Problems` (`list`, `cut`), `ButWait`
   (`at2`) and `Statement` take frames. Easy to get wrong when retiming from `vo_words.py`.

**Missing**
6. The kit has no feature-in-use scene, although features are about 45% of the film and the most important part
   ("Real UI, really used"). There is no code for the Introducing reveal (in every film), the kanban drag, the
   row-opens-into-detail, or the Bento. I built Introducing and the week-grid drag from the prose.
7. No drag helper. `cursorPos` moves on an arc (12% bow), so a dragged card interpolated in a straight line from A
   to B drifts away from the pointer mid-drag (visible in my first stills). The fix is to hang the card from
   `cursorPos(f, path)` while held; the scene library's "Kanban drag" pattern should say so, or the kit should
   export a `dragPos`.
8. `LogoOutro` needs a wordmark image file and has no text fallback; when the client has not sent a logo yet (common
   at storyboard stage) there is nothing to show. Workaround: added `wordText` / `wordSize`. The `anchor` prop
   (the point of the mark, as fractions of its width and height, that the zoom centres on; must sit inside a
   filled piece or the "screen filled by one stroke" moment shows white) is not documented.
9. `LogoOutro` starts with a bare gradient card at 640 x 360 that only makes sense after the Bento. Without the
   Bento it pops up from nothing. The kit should include the Bento or say how to enter the outro without it.
10. No guidance for a storyboard before any voice exists: the workflow says `timing.json` is written by
    `build_audio.py`, but at this stage you hand-edit it. A short "storyboard mode" paragraph (edit `timing.json`
    by hand, use the library lengths, no audio) would help.
11. No guidance on the visual size for montage cards (the left area is 1120 px wide, centred at x 560); the
    placeholder is an unstyled white div. I used 760 x 440.
12. `sheet.py` labels each still with time only. Adding the scene name and the scene frame would make mapping
    notes to scenes much easier, which the skill asks for repeatedly.

**Unclear**
13. Gradient roles: `brand.ts` says "first = warm end, middle = core, last = light end", and `Problems` treats the
    last colour as a light wash (`SKY`). For a brand whose ends are both saturated (coral and violet) there is no
    light end; the style guide says "their highlight becomes white or your light end" but not which colour plays
    the bottom wash or the fluid-field base. I kept pink as the core and violet as the "light end"; it worked, but
    by luck. Also only colours 1, 2 and the last are used anywhere, so a 4-colour gradient (allowed: "2 to 4")
    silently drops the third colour.
14. `Problems` is described as an exact reference copy ("keep it exact"). When the new client has no reference
    video, it is unclear whether to keep it frame for frame or adapt it. It also has no width guard: items sit at
    x 520 at 100 px, so anything over about 22 characters runs off the right edge ("Labour costs over budget"
    nearly did; I shortened it to "Labour over budget"). Worth stating a character limit.
15. How voice lines map to the Problems scene: the script guide lists "Turn" as its own movement and says "one line
    per scene", but the Problems scene carries both the problem list and the turn line ("Simpler" at cut + 61).
    A note on placing two lines in that one scene would help.
16. Gradient words: `Words` gives each word in a gradient part its own full gradient, so "by drag and drop." shows
    four short coral-to-violet sweeps rather than one. The style guide says "one word or phrase in the gradient",
    so it is unclear whether that is intended.
17. The opener pattern assumes a headline statistic ("Millions of marketing teams"). The brief had none; the skill
    could suggest what to do without one (I used "Hours lost to the rota every week" and flagged it).

**Worked fine / small notes**
- `npx tsc --noEmit -p .` was clean on the untouched kit and after my changes; `stills.mjs` rendered about 35 stills
  in 20 s using the symlinked `node_modules`.
- `stills.mjs` prints dozens of "Detected differing memory amounts" warnings per run in a container; harmless but
  it buries the output. Worth a note or a filter.
- `Montage.tsx` keeps an unused `dur` with a hidden `<span>`, which is a small code smell.
